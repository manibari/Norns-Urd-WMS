# 辨識 PoC 規格 — 封閉候選集命中率量測

> 2026-08-21｜對應 `docs/requirements/packaging-lot-issue-fifo.md` §6 R1、§8
> **狀態**: 待執行。這是 v1 的第一優先，**排在 mockup 之前**。

## 為什麼要做這個 PoC

Q1（改貼列印標籤）和 Q11（另貼 QR）都已答 no，v1 只能在**手蓋橡皮章**上把辨識做起來。
唯一的防線是「封閉候選集」設計（requirement §2.2）。

**這個 PoC 要回答一題：封閉候選集撐不撐得起 v1？**

答案有三種，各自導向不同的產品：

| PoC 結果 | v1 長什麼樣 |
|---------|------------|
| 命中率高、誤命中率極低 | 拍照是主路徑，人工挑批是退路 → **照現有 requirement 做** |
| 命中率不足，但誤命中率仍極低 | **人工挑批變主路徑**，拍照降為輔助 → US-2/US-4 主客易位，mockup 主畫面要換 |
| 誤命中率壓不下來 | **硬擋（US-3）不成立**，要退回軟擋（記錄 + 事後稽核，不當場攔） |

> ⚠️ 第三種是產品定位層級的改變。所以這題不能等到實作階段才發現。

---

## 1. 這個 PoC 量的不是 OCR 準確率

這是最容易做錯的一點。

系統的任務**不是**「讀出箱子上的進貨日」，而是「從該料號在庫的 1–5 個批次中挑對一個」。
兩者的成敗判準完全不同：

| 情境 | 字元正確率 | 本 PoC 判定 |
|------|:---:|---|
| 讀成 `2026-08-l2`（1 誤認為 l），候選集裡只有 `2026-08-12` 接近 | ❌ 錯 | ✅ **命中** |
| 讀出 `2026-08-12` 完全正確，但候選集裡有 `08-12` 和 `08-13` 兩批，系統挑了 `08-13` | ✅ 對 | ❌ **誤命中** |
| 章糊掉讀不出，系統說「不確定」 | ❌ 錯 | ⚪ **退人工**（可接受） |

→ **報「總準確率」一個數字是沒有意義的，必須分開報三個。**

---

## 2. 三個指標

對每一張照片，系統輸出必為以下三者之一：

```
hit        挑了一個批次，且與 ground truth 相同
false_hit  挑了一個批次，但挑錯了 —— 系統以為自己對
defer      系統回報「不確定」，轉人工（US-4）
```

| 指標 | 定義 | 性質 |
|------|------|------|
| **命中率** | `hit / total` | 體驗指標 —— 決定「拍照省事」這個賣點成不成立 |
| **誤命中率** | `false_hit / total` | ★ **安全指標** —— 決定硬擋成不成立 |
| **退人工率** | `defer / total` | 成本指標 —— 決定現場多花多少時間 |

### 為什麼誤命中率是最嚴的一條

誤命中 = 系統挑了錯的批次、扣了錯的庫存、通過了 FIFO 檢核、**什麼都沒報錯**。
不報錯、log 乾淨、稽核翻紀錄也看不出來 —— 這正是 requirement §2.2 要消滅的失敗模式。

退人工只是慢；誤命中是**核心價值破洞**。兩者不能用同一個門檻看待。

---

## 3. 通過門檻（建議值，執行前請確認）

| 指標 | 門檻 | 理由 |
|------|------|------|
| 誤命中率 | **< 0.5%** | 若一天領 50 箱，1% ≈ 每兩天一筆假放行。GMP 稽核場景不能接受 |
| 命中率 | **≥ 80%** | 低於此，作業員會覺得「拍了還是要自己選」，拍照的價值感消失 |
| 退人工率 | **≤ 20%** | 與命中率互補；此處單獨列出是為了讓「保守退人工」成為可接受的策略 |

**策略上的重點：寧可 defer，不要 false_hit。**
prompt 與門檻設計應偏保守 —— 不確定就退人工。退人工率換誤命中率是划算的交易。

---

## 4. ⚠️ 樣本數的統計誠實

**200 張樣本無法證明誤命中率 < 0.5%。**

若 200 張中出現 0 次誤命中，95% 信心上界約為 **1.5%**（rule of three: 3/n）。
也就是說，PoC 通過只代表「沒有明顯問題」，不代表達標。

→ 對策（兩者都要）：
1. **樣本數優先花在「難的那一半」** —— 見 §5 的分層抽樣。均勻拍 200 張簡單的箱子沒有資訊量。
2. **上線後持續監測** —— US-9 的異常告警要包含誤命中的代理指標
   （例：覆核時被主管改批次的比率、追溯查詢時發現對不上的比率）。
   PoC 只是開門檢查，不是最終驗收。

## 5. 資料集：現場實拍 100–200 張

### 5.1 分層抽樣（不要均勻拍）

樣本要**刻意偏向困難情境**，因為系統會不會壞由困難情境決定：

| 分層 | 目標張數 | 說明 |
|------|:---:|------|
| 章清晰、正面拍 | 30 | 基準線 |
| **章墨色偏淡 / 偏濃糊成一團** | 40 | R1 的核心困難 |
| **章蓋歪、出框、蓋到印刷字上** | 30 | 同上 |
| 斜角拍 / 距離遠 / 手震 | 30 | 現場實際手持狀況 |
| 光線不足 / 反光 / 逆光 | 30 | 包裝區照明條件 |
| 箱子堆疊、綑帶部分遮擋 | 20 | 實照 `IMG_2930.jpg` 顯示的情形 |
| 標籤磨損 / 髒污 | 20 | — |

> 拍攝時**每張都要能對到一個已知的真實批次**，否則無法標 ground truth。

### 5.2 ★ 候選集怎麼來（PoC 能不能做對的關鍵）

系統還沒上線、沒有庫存資料，但 PoC 必須有候選集才能量。兩種做法：

**做法 A（推薦）— 拍攝當下請倉管報在庫批次**
拍每一箱時，同步記錄「該料號此刻在庫有哪幾批（料號 + 進貨日 + 製造日）」。
這是最真實的候選集，也順便量到**候選集大小的真實分布**——這個分布本身就是重要發現。

**做法 B（退而求其次）— 從樣本集反推**
把拍到的所有箱子按料號分組，同料號的不同進貨日即構成該料號的候選集。
缺點：反映的是「拍到的」而非「在庫的」，候選集會偏小 → **命中率會被高估**。
若用 B，報告必須註明此偏差。

### 5.3 標註格式

每張照片一列，建議 CSV：

```csv
photo_id,item_code,receipt_date_truth,manufacture_date_truth,stratum,candidate_lots,notes
IMG_3001,2003.T7320BC-340X900-P1,2026-08-12,2025-09-26,stamp_faint,"2026-08-12|2026-06-03|2026-04-10",章偏淡
```

- `receipt_date_truth` — **由人現場核對箱上實章抄下**，不是從照片事後猜
- `candidate_lots` — 該料號當下在庫的所有進貨日，`|` 分隔
- `stratum` — §5.1 的分層標籤，用於分層報告

> 📌 requirement §2 有記一個教訓：章面公司名「金軒揚」曾被人在放大照片上抄成「鑫軒揚」。
> **人在照片上都會抄錯** → ground truth 一定要現場對實體箱子抄，不能事後看照片標。

## 6. 執行方式

不需要建任何系統。一支腳本即可：

```
讀 CSV → 對每張照片：
  1. 呼叫辨識 API（影像 → JSON：料號 / 製造日 / 進貨日 / 各欄信心度）
  2. 正規化（四種日期格式 → 標準值；型號簡寫 → 完整料號）
  3. 與 candidate_lots 比對：
       唯一接近命中 → 輸出該批次
       命中 0 個或 >1 個 → defer
  4. 與 receipt_date_truth 比對 → 判定 hit / false_hit / defer
→ 輸出：總表 + 分層報告 + 候選集大小分層報告
```

**正規化那段是純函式，先寫先測。** 它在 v1 的人工輸入版也要用（requirement US-4），
所以這不是 PoC 拋棄式程式碼，是 v1 的第一塊正式程式。

### 要跑幾種設定

至少跑這幾組，因為結論可能差很多：

- 單張 vs **連拍 3–5 張擇最清晰**（requirement US-2 的設計，PoC 應驗證它值不值得）
- 全圖 vs 只裁章的區域
- 不同信心度門檻（掃過一遍，畫出「誤命中率 vs 退人工率」的取捨曲線）
- **模型層級**（見下）

### 已測：模型層級（2026-08-21，IMG_2928 × 3 次）

| 模型 | 中位耗時 | 型號＋兩個日期全對 |
|---|---:|---|
| `gemini-pro-latest` | 19.1s | 3/3 |
| `gemini-3.7-flash` | **8.4s** | 3/3 |
| `gemini-3.5-flash`（無 thinking） | 11.8s | ✗ 進貨日讀錯 |

→ 預設改用 **gemini-3.7-flash + thinking**。單張樣本不足以定論準確率，
但「快一倍而讀出來的東西一模一樣」已足以決定預設值；真 PoC 仍須依 §5.1 分層實拍驗證。

⚠️ 單次計時會騙人：pro 第一次跑出 6.9s，看起來比 flash 還快，中位其實是 19.1s。
量模型速度**至少跑三次取中位**。

## 7. 報告要長什麼樣

除了三個總指標，**必須有這兩張分層表**：

**① 按候選集大小分層** — 這張決定 §2.2 的設計成不成立

| 候選集大小 | 樣本數 | 命中率 | 誤命中率 | 退人工率 |
|:---:|---:|---:|---:|---:|
| 1 批 | | | | |
| 2 批 | | | | |
| 3–4 批 | | | | |
| 5+ 批 | | | | |

> 預期命中率隨候選集變大而下降。若 5+ 批時誤命中率明顯升高，
> 對策不一定是改辨識 —— 也可能是**收貨端減少同料號並存批數**（流程解，通常更便宜）。

**② 按拍攝分層** — 這張決定要不要改現場條件

| 分層 | 樣本數 | 命中率 | 誤命中率 |
|------|---:|---:|---:|
| （§5.1 各層） | | | |

> 若「光線不足」那層特別差，解法是**包裝區加一盞燈**，不是調 prompt。
> 這類流程/硬體解通常比模型調校便宜十倍，但只有分層報告才看得出來。

## 8. 不通過怎麼辦（先想好，免得當場慌）

| 症狀 | 對策（由便宜到貴） |
|------|------------------|
| 某一拍攝分層特別差 | 改現場條件：加燈、規定拍攝距離、教作業員擦一下章面 |
| 5+ 批時才變差 | 收貨端控制同料號並存批數；或該類料號預設走人工挑批 |
| 命中率普遍不足、誤命中率仍低 | **US-4 升為主路徑**，改 requirement 與 mockup（不是災難，紀錄仍完整） |
| 誤命中率壓不下來 | **硬擋不成立** → 退軟擋：照記錄、當場提示但不攔，靠 US-10 報表事後稽核。需回頭改 US-3 |
| 全面不行 | 回頭談 Q11（另貼 QR）—— Peter 已說「未來可能可以」。屆時 PoC 數據就是說服的材料 |

> 最後一列是重點：**這份 PoC 的數據，本身就是未來重談 Q11 的籌碼。**
> 「我們試過了，手蓋章在現場條件下只能到 X%」比「我覺得會很難」有力得多。
