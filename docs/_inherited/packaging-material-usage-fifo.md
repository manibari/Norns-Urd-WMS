## 1. Goal — Who / What / Why

### 一句話
包裝線工人領用內包材時，**拍箱子取代抄表單** —— 自動辨識型號/製造日/進貨日，
即時檢查是否先進先出，不是 FIFO 就不准登錄領用。

### Who
| 角色 | 說明 |
|------|------|
| **包裝線作業員** | 上膜/下膜時領用包材；目前手抄紙本表單 |
| **倉管** | 驗收時蓋進貨日期章；處理辨識失敗與 FIFO 例外 |
| **廠長 / 品管主管** | 稽核追溯紀錄（GMP 文件）、覆核非 FIFO 領用 |
| **會計** | 消費領用事件 → 包材耗用分錄 |

### What — 取代什麼
現行紙本：**「內包材使用紀錄表」文件編號 P-4-P-01-07**（成品包裝區—肉乾），
修訂日期 2025/12/30，主管簽核黃海山。九個欄位全靠手抄：

| 欄位 | 來源 | 可否 OCR |
|------|------|:---:|
| 日期 | 系統時間 | 自動 |
| 上膜 / 下膜 | 作業員選 | ✗ 人選 |
| **包材型號** | 箱上標籤（印刷） | ✓ OCR |
| **包材進貨日** | 箱上**倉管驗收紅章**（手蓋） | ✓ OCR（最難） |
| **包材製造日** | 箱上標籤（印刷） | ✓ OCR |
| 包裝產品 | 作業員選（追溯鏈關鍵） | ✗ 人選 |
| 使用步徑 | 機台碼表讀數（如 557/326） | ✗ 人填 |
| 包裝機台 | D-003 / D-004 / D-023 / D-027 | ✗ 人選 |
| 記錄人 | 登入身分 | 自動 |

> → 介面**不是純拍照**，是「拍照自動帶 3 欄 + 人工選填 4 欄 + 系統帶 2 欄」。

### Why
1. **FIFO 失控無人即時發現** — 紙本上已看得到違規（見 §2 證據 D），但要事後翻表才知道，舊包材壓倉底直到過期。
2. **手抄成本與錯誤** — 作業員要跑去看箱子側面的章、抄兩個日期，字跡潦草、格式不一。
3. **追溯鏈斷裂** — 「哪批膜包了哪批成品」只存在紙上；召回時要翻箱倒櫃。
4. **GMP 稽核** — P-4-P-01-07 是品質文件體系的一環，數位化後可即時稽核而非年度翻檔。

表單備註第 5 條明文：「內包材於倉管驗收會蓋上進貨日期章，請將進貨日期填寫於表單上。」

> ⚠️ **FIFO 排序鍵是一枚手蓋橡皮章** —— 全案最難辨識的欄位，偏偏最關鍵。

> 📌 2026-08-21 更正：本節原將章面公司名抄成「**鑫**軒揚」，實為「**金**軒揚」（客戶確認）。

> **人在放大的照片上都抄錯了，這正是辨識模型會犯的同一類錯**，
> 也是為什麼設計上不讓辨識結果當真相、而是拿去比對已知在庫批次（見架構文件 §2）。

### C. 頂面只有中文標，沒有驗收章（`IMG_2930.jpg`）
從上方俯拍的箱子，頂面標籤只有料號 `2003.T6240BA-334X600` 與製造日期 `2025年06月01日`，
**沒有進貨日章**。章蓋在側面，堆疊 + 綑帶會遮擋。

### D. 紙本表單本體與既存 FIFO 違規（`IMG_2921.jpg`）
表單上多數列包材進貨日為 `20260410`、製造日 `20250926`，
但**第 7 列用的是進貨日 `20260303`、製造日 `20260118`** 那一批。
若 `20260303` 批仍有庫存，則前面各列使用 `20260410` 即為非 FIFO。
→ **違規實例已存在於現行紙本**，證明本需求有真實標的，不是假想問題。

### E. 表單註記（原文）
1. 肉乾真空膜不需填寫有效日期，肉鬆產品應填寫脫氧劑日期資訊，年份請用西元。
2. 夾鏈鋁袋及罐裝鋁袋，須填寫包裝產品（例如：海香、海魚、豬脆、香酥、魚絲、雞脆）。
3. 肉乾類產品須填寫包裝產品（例如：經典、豬切、牛切、休閒豬、金尊）。
4. 若製造同一產品時，用到不同製造日、進貨日的包材，也要確實記錄。
5. 內包材於倉管驗收會蓋上進貨日期章，請將進貨日期填寫於表單上。
6. 包裝機台編號：1號 D-003、2號 D-004、3號 D-023、4號 D-027。

## 3. 已定案決策與待重議

| # | 決策 | 選定 | 現場照片的驗證結果 |
|---|------|------|------|
| D1 | FIFO 違規強度 | **硬擋 — 不 FIFO 不准出帳** | 維持。需 override 通道（§6 R2） |
| D2 | FIFO 排序基準 | **進貨日 (receipt_date)** | ✅ **實證支持** — 表單就是記「包材進貨日」+「包材製造日」兩欄 |
| D3 | 辨識管道 | ~~倉庫固定相機自動拍~~ | ⚠️ **建議重議**，見下 |
| D4 | 比對顆粒度 | **每掃一箱即時比對** | 維持。對應「每次領用一箱」 |

### D3 需要重議的三個理由（來自照片）
1. **拍不到關鍵欄位** — 進貨日章在側面，箱子堆疊 + 綑帶遮擋（證據 C）。
2. **領用點分散** — 四台包裝機 D-003 / D-004 / D-023 / D-027，不是單一通道。
3. **本來就有五個欄位要人工填選** — 作業員必然要操作裝置，固定相機省不掉這一步。

→ **建議改為手機／平板拍照**：作業員原本就要抄表，改成「拍一張 + 點選四格」是淨減法。
→ 此題我不自行拍板，列為 §7 Q1，需你決定。

## 4. 前提地基（現有計畫缺少，必須先補）

現行模型：`product` → 庫存數量（品項層級）。
本需求要求：`product` → **批次 (lot)** → 在庫數，批次帶進貨日/製造日。

- `inventory_lot`
  - `product_id` — 對映包材料號（如 `2003.T7320BC-340X900-P1`）
  - `receipt_date` — 進貨日 **← FIFO 排序鍵**（來自倉管驗收章）
  - `manufacture_date` — 製造日（記錄與追溯用，非排序鍵）
  - `supplier_lot_code` — 原廠 ROLL#（如 `20250915-3081*61`）
  - `warehouse_id` / `qty_on_hand` / `source_receipt_id`

- `material_usage_scan`（每次領用一筆）
  - `captured_at` / `captured_by` / `image_url`（原始影像必留 — 稽核唯一證據）
  - `ocr_raw` / `confidence`
  - OCR 帶出：`product_id` / `manufacture_date` / `receipt_date`
  - 人工填選：`film_position`(上膜/下膜) / `packed_product` / `usage_meter` / `machine_id`
  - `status` — `pending` | `posted` | `blocked_fifo` | `blocked_unreadable` | `overridden` | `voided`
  - `fifo_expected_lot_id` / `override_by` / `override_reason`

- **正規化對映表**（照片實證的必要性）
  - 型號：標籤 `2003.T7320BC-340X900-P1` ↔ 表單簡寫 `T7320-P1`
  - 日期四種格式並存：`2025年09月26日` / `26-Sep-25` / `2026-08-12`(章) / `20250926`(表單)

> ⚠️ 影響上游：入庫 (M2) 必須按批次登錄進貨日，否則領用端沒有比對基準。

## 5. 與現有 ERP 的接線（不重造輪子）

**結論：這是 ERP 的一個模組（M7 — 包材領用稽核），約 8 成接既有、2 成新造。**

| 既有資產 | 本模組怎麼用 |
|---------|------------|
| `posting_service`（Phase 2） | 領用落帳走既有唯一過帳入口 |
| `audit_log.py` | override 覆核、人工補登軌跡 |
| RBAC | 「誰能覆核非 FIFO」是既有權限模型的新權限 |
| M1 product 主檔 | 包材料號進主檔（**現有 89 品項是成品，包材要另建**） |
| antd 前端外殼 | 待補登佇列、違規報表、追溯查詢是新頁面 |
| Alembic | 批次層 schema 沿用既有 dev↔prod 同步 |

### 事件接線
```
M2 採購入庫 ──(新增：按批次登錄 receipt_date = 驗收章日期)──> inventory_lot
                                                                  │
                                                                  ↓ FIFO 比對基準
包裝線拍照 ──> material_usage_scan ──> FIFO 檢核 ──> 扣 lot 庫存
                        │                   │              │
                   人工補 4 欄               │              └─> posting_service ─> M5 分錄
                        │                   └──(違規)──> 警示 + 待覆核佇列
                        ↓
                   追溯鏈（包材批次 ↔ 成品批次）
```

### 真正新造的三塊
1. **`inventory_lot` 批次層** — 唯一地基改動，**會回頭改 M2 入庫**
2. **`material_usage_scan` + 辨識服務** — 拍照、OCR、正規化、信心度門檻、影像留存
3. **FIFO 判定 + 警示 + 追溯查詢**

### 對 `task_plan.md` 的衝擊
- Phase 3（主檔）要加批次概念 + 包材品類
- Phase 4（M2 入庫）從「品項收貨」改成「批次收貨」
- 計價法若維持加權平均，會是「實物 FIFO、成本加權平均」並存（會計上合法但要確認）

> **不建議**做成獨立系統再對接 ERP：批次資料的 SoT 只能有一份。

## 6. User Stories

### US-1: 拍照領用登錄
**As a** 包裝線作業員
**I want** 拍一張箱子就帶出型號/製造日/進貨日
**So that** 不用跑去看側面的章再手抄

**驗收標準**
- [ ] 拍照後自動辨識並回填三欄，作業員可就地更正
- [ ] 人工選填：上膜/下膜、包裝產品、包裝機台（D-003/D-004/D-023/D-027）、使用步徑
- [ ] 日期與型號經正規化對映後才入庫（§4 對映表）
- [ ] 原始影像永久留存並可從紀錄點開
- [ ] 通過 FIFO 檢核 → `status=posted`，扣 `inventory_lot.qty_on_hand`
- [ ] 扣庫存與領用紀錄在**同一 DB transaction**

### US-2: 非 FIFO 硬擋並即時警示
**As a** 包裝線作業員 / 倉管
**I want** 拿錯批次的當下就知道
**So that** 還來得及換一箱

**驗收標準**
- [ ] 查詢該料號 + 倉庫下 `qty_on_hand > 0` 的最早 `receipt_date`
- [ ] 掃到的 `receipt_date` > 最早值 → 違規
- [ ] 違規 → `status=blocked_fifo`，**不扣庫存、不落帳**
- [ ] 畫面明示「應領用：進貨日 YYYY-MM-DD 那批（位置／批號）」
- [ ] 同一進貨日多批視為並列合法
- [ ] 違規紀錄不可刪除，僅可經 US-4 覆核或主管作廢（需原因）

### US-3: 辨識失敗的人工補登
**As a** 作業員
**I want** 章糊掉、標籤磨損時能手動填
**So that** 不會卡住整條包裝線

**驗收標準**
- [ ] 信心度低於門檻或欄位缺漏 → `status=blocked_unreadable`
- [ ] 就地手動填寫，**仍須通過 US-2 的 FIFO 檢核**
- [ ] 記錄操作者與時間
- [ ] 待補登佇列堆積超過門檻 → 升級通知主管

### US-4: 合法非 FIFO 的覆核放行
**As a** 廠長／品管主管
**I want** 對正當例外放行
**So that** 現場不會為了趕產線而繞過系統

**驗收標準**
- [ ] `blocked_fifo` 可由具權限者放行，**必須填選原因**
      （試產指定批 / 舊批破損不可用 / 規格臨時變更 / 急單 / 其他+說明）
- [ ] 放行後 `status=overridden` 並正常落帳扣庫存
- [ ] 覆核者、時間、原因寫入 audit_log
- [ ] 一般作業員**無**此權限

### US-5: 追溯查詢（GMP 召回用）
**As a** 品管
**I want** 從包材批次查到所有用它包過的成品，反向也要能查
**So that** 召回時不必翻紙本

**驗收標準**
- [ ] 正向：給包材批次（料號＋進貨日＋製造日）→ 列出所有領用紀錄與包裝產品
- [ ] 反向：給成品 → 列出用過的所有包材批次
- [ ] 每筆可 drill-down 到原始影像
- [ ] 可匯出為等同 P-4-P-01-07 格式的稽核報表

### US-6: FIFO 違規追蹤報表
**As a** 廠長
**I want** 看違規次數、原因分布、常違規的品項與班別
**So that** 知道是人的問題、儲位的問題，還是流程的問題

**驗收標準**
- [ ] 依期間列出 `blocked_fifo` + `overridden` 筆數與比率
- [ ] 依 override 原因、料號、機台、班別分組排名
- [ ] drill-down 到單筆紀錄與影像

## 7. 明確風險

**R1 — 進貨日是手蓋橡皮章，是全案最大技術不確定性。**
FIFO 排序鍵的唯一來源是紅色橡皮章（證據 B）：歪斜、墨色深淺不一、蓋在瓦楞紙上、
可能蓋歪出框或蓋到印刷字上。印刷標籤 OCR 是成熟問題，**手蓋章不是**。
→ 若辨識率不足，替代方案：驗收時**改貼列印標籤（含 QR）**取代橡皮章。
   這是流程改動，但可能比硬解 OCR 便宜十倍，且一次解決型號與批號。

**R2 — 沒有 override 通道，現場必然繞過系統。**
硬擋 + 無正當例外出口 = 作業員學會不拍照直接用。
比軟擋更糟：資料全綠，實際失控。US-4 是硬擋成立的前提，不是加分項。

**R3 — 「硬擋」擋不住物理領用。**
系統只能擋帳與警示，擋不住人把膜裝上機台。
→ 必須接受「已用但未落帳」的中間狀態，並設計清空機制（US-3 升級通知）。

**R4 — 包材主檔目前不存在。**
現有 89 品項是成品。包材料號（`2003.T7320BC-340X900-P1` 等）要另建主檔並匯入。
